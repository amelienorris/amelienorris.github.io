The problem

LLMs rarely get one clean instruction. They get a system prompt, a user request, tool output, and house rules, and some of those disagree.

The quiet failure is a model that breaks one of the rules and never mentions it. ConstraintBench measures how often that happens.

It sorts tasks by how hard the conflict is, from none at all to rules that cannot both be true, and scores each response on three plain metrics.

Live-model evaluation is paused because of API costs. The available replay uses stored demo-mode outputs.

How it works

  1. Constraints arrive as bricks and stack on the prompt.

    Each benchmark item is a task plus 3 to 7 constraints. Baseline items have no conflict. Soft-conflict items have a priority you can infer. Hard-conflict items cannot all be satisfied. Scaling items pack 6 to 8 constraints with conflicts buried inside.

  2. Bricks that contradict each other get a red outline.

    The conflict is part of the item, so the benchmark knows ahead of time which constraints clash, for example "list exactly 3 languages" next to "list exactly 5 languages".

  3. The model writes its response.

    The prompt lists every constraint and a system prompt tells the model to say so if instructions conflict. In live mode this goes to the Anthropic API.

  4. Each constraint lights green if kept, gray if broken.

    Every item has a checker function: word counts, required words, endings, banned words. Each check passes or fails.

  5. The conflict flag goes up only if the response names the conflict.

    A response counts as flagging the conflict when it says so in words such as "conflict", "contradict", or "cannot".

  6. CSR, CDR, and RA meters fill.

    CSR is the share of non-conflicting constraints satisfied. CDR is 1 if the response acknowledges the conflict. RA is 1 when CSR is at least 0.8 with no conflict, or when a conflict is present and detected; otherwise 0.
